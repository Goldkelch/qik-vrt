# Mesh Autonomous Publication, Terminal Pattern and Compiled Pattern Capsules V1

## Purpose

This contract closes four connected but previously separate gaps:

1. a failed semantic model step must not erase deterministic repository progress;
2. one lossless Terminal Pattern must support Watchdog, operator, owner and public views without creating four competing states;
3. reusable repository intelligence must be exportable as a content-addressed Pattern Capsule without cloning credentials, identity or canonical Authority;
4. every eligible finite control decision must execute through the proof-bound Motorola 68000 Spark kernel, while Git, credentials, semantic inference and platform effects remain in the bounded host adapter.

## First deterministic publication blocker

The previous issue-agent path converted any failed model inference into one coarse `BLOCK`. A historical repair existed in PR #95, but it was stale and unmerged. The running workflow also rebuilt the issue branch from the default branch instead of restoring its prior cursor, so a work-unit state could not be a durable resumable history.

The current repair therefore:

- restores the existing `issue-agent/<issue>` branch;
- merges current Authority `main` history-preservingly;
- excludes the issue's own generated evidence from its source inventory;
- binds work-unit inputs to the current Authority head rather than to self-generated terminal commits;
- completes deterministic discovery, inventory and hashing before a semantic hold;
- persists the exact first blocked unit and next action;
- does not create a new state commit for the same unresolved input.

`MODEL_INFERENCE_UNAVAILABLE` is now a scoped semantic-unit blocker, not a claim that no repository work can continue.

## Platform publication is an executable stage

A public GitHub branch or pull request is a repository publication effect. It is not a Zenodo publication.

A publication-required issue cannot become `DONE` merely because its repository answer is complete. It must carry one committed `qikvrt_issue_publication_route_v1` route that binds:

- the platform;
- the exact v2 manifest path and SHA-256;
- the trusted adapter;
- the normalized effect-receipt path.

For Zenodo, the trusted scheduled workflow executes the already-existing generic publisher only after:

- repository work is pre-effect ready;
- the route and manifest are committed and clean;
- the v2 machine-proof bundle and candidate-specific owner authorization exist;
- the M68000 finite readiness kernel returns `NOOP_COMPLETE`;
- `ZENODO_ACCESS_TOKEN` is available only inside the effect step.

The generic publisher owns the credentialed network mutation, single-use authorization-consumption ref, exact upload set, public DOI/record observation and byte-redownload verification. Interrupted effects persist their exact recovery evidence and must reconcile the same remote state; they may not create a duplicate record.

After `PUBLIC_VERIFIED`, the issue branch receives the normalized effect receipt and only then becomes eligible for the existing Authority merge, Mirror synchronization, common tag and issue closure transaction.

Unsupported platforms remain a precise `EXTERNAL_HOLD_NO_BOUND_ADAPTER`; they are not silently treated as Zenodo and are not falsely reported as published.

## One Terminal Pattern

The canonical Terminal Pattern is one lossless receipt. It contains the exact source payload bytes as Base64 plus byte length and SHA-256, exact repository/ref/head/tree binding, parsed status and the finite M68000 decision receipt.

Four views are derived from that one receipt:

- `WATCHDOG_FULL`: the entire canonical receipt, losslessly;
- `OPERATOR`: exact binding, status, first blocker, next action and effect state;
- `OWNER`: effect class, first blocker, next action, machine-owned remainder and whether an owner decision is actually required;
- `PUBLIC`: bounded non-sensitive effect and evidence state.

Every view binds the same `receipt_sha256`.

```text
VIEW_DIFFERENCE != STATE_DIFFERENCE
SUMMARY != AUTHORITY
PUBLIC_REPOSITORY_EFFECT != PLATFORM_PUBLICATION
```

## Pattern Capsule and cloning boundary

A Pattern Capsule exports the finite decision table, preconditions, invariants, terminal projection rules, effect-adapter interface, test vectors and receipt bindings.

It deliberately does not export:

- repository ownership or canonical Authority;
- credentials, tokens or external account access;
- natural-person identity or authorship;
- candidate-specific owner authorization;
- legal, licensing or rights decisions;
- stale `PASS`, `FINAL_PASS` or `EFFECT_ACK_DONE`.

A clone must establish a new origin/upstream relation, exact head/tree, authority and credential binding, and fresh tests and receipts. The capsule transfers reusable intelligence, not legal or operational authority.

## M68000 compiler coverage

The existing `lean_spark_branch_pass_v1` machine kernel is now the common finite decision path for:

- issue work-unit continuation;
- Terminal Pattern readiness;
- Pattern Capsule eligibility;
- platform-publication handoff readiness.

Its input remains one eight-bit control byte:

```text
bit 0 IMPLEMENTED
bit 1 VERIFIED
bit 2 PERSISTED
bit 3 REOBSERVED
bit 4 STALE_EVIDENCE
bit 5 AUTHORITY_REQUIRED
bit 6 AUTHORITY_PRESENT
bit 7 UNCLASSIFIED_REMAINDER
```

Its output remains:

```text
D0=0 NOOP_COMPLETE
D0=1 HOLD
D0=2 REOBSERVE
D0=3 REQUEST_AUTHORITY
```

D1 is the completion witness, D2 is machine-owned reobservation activity and D3 is preserved exactly.

“Repository-wide compiler use” means every eligible total finite control pattern passes through this kernel or a later exact compiled kernel. It does not mean that arbitrary text, Git, HTTPS, credentials, semantic judgment or a platform API is converted into one local instruction.

```text
M68000_PLAN_SELECTION != GITHUB_OR_ZENODO_EFFECT
VIRTUAL_M68000_EXECUTION != PHYSICAL_M68000_EXECUTION
QIKVRT_CIRCULAR_SPARK_ARCHITECTURE != SUN_SPARC_ISA
```
