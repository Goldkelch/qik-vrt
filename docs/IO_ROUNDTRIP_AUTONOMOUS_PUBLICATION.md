# I/O Round-Trip: repository persistence to proven publication

This contract implements the Product Owner requirement that every artifact crossing an artificial-cognitive input/output boundary is durably representable in QIK-VRT before any derived external publication occurs.

## Invariant

`INPUT_OR_OUTPUT -> CONTENT_ADDRESS -> REPOSITORY_ENVELOPE -> EPISTEMIC_CLASSIFICATION -> GRANULARITY -> CONNECTABILITY -> MACHINE_PROOF_RECEIPT -> PUBLICATION_QUEUE -> ZENODO -> IETF_WHEN_APPLICABLE -> EFFECT_RECEIPT`

The first transition is unconditional for accepted interface events: persistence is not contingent on whether the material is novel, true, publishable, textual, acoustic, visual, binary, generated by a tool, or supplied by a human. Publication is conditional.

## Executable entrypoint

```sh
python3 -B tools/qikvrt_io_roundtrip.py --input envelope.json
```

To allow configured publication adapters to execute after eligibility has been established:

```sh
QIKVRT_EXTERNAL_EFFECT_AUTHORIZATION=ZENODO \
QIKVRT_ZENODO_PUBLISH_CMD='python3 -B tools/qikvrt_zenodo_actions.py ...' \
python3 -B tools/qikvrt_io_roundtrip.py --input envelope.json --execute-effects
```

IETF submission uses the same fail-closed structure through `QIKVRT_IETF_SUBMIT_CMD` and additionally requires `ietf_applicable=true` in the bound envelope. The command adapter is intentionally externalized so the repository can bind the exact reviewed submission client rather than silently inventing Datatracker credentials or protocol semantics.

## Publication qualification

A repository envelope may enter the Zenodo publication queue as `NEW_KNOWLEDGE` only when all of the following are machine-readable facts: a machine-proof receipt is bound, the unit has eligible publication granularity, the result is connectable to the canonical knowledge graph, and the exact artifact SHA-256 is bound. This is a qualification result, not a claim of empirical truth or scientific consensus.

IETF suitability is stricter: the same archival requirements apply, `ietf_applicable` must be true, and the eventual submission adapter must bind the exact Internet-Draft bytes and authorization used for the external effect.

## Automation

`.github/workflows/qikvrt_io_roundtrip.yml` provides the repository-native dispatcher. It persists changed `evidence/io-roundtrip/**` bytes back to the triggering branch and can execute external adapters only when the workflow is explicitly invoked with effects enabled and the corresponding repository authorization/configuration is present.

A conforming interface SHOULD invoke the round-trip orchestrator for every input and output event it is able to observe. Interfaces that cannot write the repository MUST surface that limitation rather than claiming audit-complete persistence.

## Evidence boundary

Formal proof is model-relative. Publication does not imply truth, independent empirical confirmation, scientific consensus, `PASS`, `FINAL_PASS`, or `EFFECT_ACK_DONE`. Effect receipts establish only the external effect they actually bind.
